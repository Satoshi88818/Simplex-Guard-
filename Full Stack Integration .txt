Full Stack Integration — Risk-Aware Planner + Hard Safety Guard + Closed-Loop Sim

Wires together the three previously-built, independently-validated pieces into one closed loop, the way the original FSD v12 design document's architecture intends:

ILQRPlanner (risk-aware, "smart" upstream planner) | v SimplexGuard (dumb, deterministic, hard safety backstop) | v Closed-loop simulator (drives both through scripted scenarios) 

Everything below was actually written, executed, and debugged — including two real integration bugs the process caught (Section 3), a third real bug in the collision-geometry model exposed by finally using lateral obstacle offsets (Section 4), and a direct, empirical answer to the open question from the previous deliverable (Section 5).

No real data anywhere — same synthetic scenarios as before, now with a risk-aware planner in the loop instead of only the obstacle-blind one.

1. What's new here vs. the three standalone pieces

Nothing in simplex_guard.py, closed_loop_sim.py, or stochastic_ilqr.py was modified — all three are imported unchanged (bundled in full below for self-containment). The new glue code is entirely in full_stack_integration.py:

2. Headline result

Same obstacle (2m × 1.5m, stationary, 1m off the lane centerline, 30m ahead), same start speed, same guard, same everything — only the planner differs:

The naive planner needs the guard to intervene constantly just to avoid a high-speed impact, and still makes contact — because the guard can only brake, it cannot steer. The risk-aware planner sees the same obstacle information, routes around it on its own, and barely needs the guard at all. This is the concrete, measured version of the argument for why upstream risk-awareness (Improvement #1) and a hard safety backstop (Improvement #5) are complementary, not substitutes.

3. Two real integration bugs (found while wiring the pieces together, not before)

Bug 1 — the planner's speed command silently ignored the vehicle's actual speed

The kinematic-unicycle model used by the standalone iLQR solver treats speed as an instantaneously-settable control, not a continuous state — there's no inertia constraint tying the solver's first chosen control to where the vehicle actually is right now. My first version of the glue code built the returned trajectory using the solver's first control (U[0]) as if it were "the current state," then extracted acceleration by differencing two points inside the plan. Since the plan has no idea what the vehicle's real speed is, the result was a planner that could (and did) command effectively instantaneous speed changes: starting from 10 m/s, the very first closed-loop test showed the ego essentially staying at ~10 m/s for several cycles rather than smoothly ramping toward the 15 m/s cruise target — the extraction logic was numerically stable but physically meaningless.

Fixed by anchoring index 0 of every returned trajectory to the ego's actual measured current speed (not the solver's opinion of what it should be), and deriving the applied acceleration from the transition traj[1] - traj[0] — restoring the same state-trajectory convention the guard and the naive planner already used, and adding an explicit, physically-motivated max_accel_mps2 clamp in the simulator so no planner (risk-aware or not) can command an unrealistic instantaneous speed jump.

Bug 2 — fixing Bug 1 broke curvature, by conflating "current state" with "the plan's decision"

The natural-looking fix for Bug 1 — "just use the ego's real state at index 0 for everything" — is wrong for curvature specifically. Speed needs continuity (it's a real physical quantity with inertia); curvature/turn-rate in this model is a directly commandable instantaneous rate, exactly like the naive planner's own traj[0, curvature] (which is always the freshly chosen curvature for right now, never "whatever curvature was last applied"). Using last_curvature at index 0 meant the guard's extraction of curvature_cmd = safe_traj[0, 4] kept re-applying the previous cycle's steering command forever — the risk-aware planner's freshly computed avoidance maneuver was being computed correctly every cycle and then silently never applied. This is exactly why the very first "fixed" test run of the off-path obstacle scenario showed the iLQR planner colliding too (identical to the naive planner's outcome) — the fix for Bug 1 had accidentally deleted all steering.

Fixed by keeping index 0's speed anchored to the ego's real state (for Bug 1's sake) while keeping index 0's curvature as the solver's fresh first-control decision (matching the convention used everywhere else in this project). Both bugs are locked in as explicit regression tests (test_index_zero_speed_is_actual_ego_speed_not_solver_control, test_index_zero_curvature_is_fresh_plan_not_stale_last_curvature).

4. A third real bug: the previous deliverable's collision check was quietly wrong for this scenario

The earlier closed-loop simulator's collision/clearance check was longitudinal-only — a documented, deliberate simplification, valid only because every obstacle in that deliverable shared the ego's lane exactly (lateral_offset_m didn't meaningfully vary). The moment this integration needed an obstacle off to the side — the natural scenario for demonstrating risk-aware routing — that simplification became actively wrong: it flagged a "collision" for anything sharing the ego's x-range, regardless of how far away it was laterally. The very first attempt at the headline comparison scenario showed both planners colliding, which didn't match the closed-loop trace at all (the iLQR planner was visibly steering around the obstacle, min_dist metric said otherwise only because it wasn't measuring the right thing).

Fixed with a proper 2D axis-aligned rectangle separation check (FullStackSimulator._rect_separation), and ego_width_m added as an explicit simulator parameter (the previous deliverable never needed one). This is a real correction to a previously-shipped, previously- "validated" component — the earlier deliverable's own same-lane tests remain completely valid (the two checks agree exactly when lateral offset is zero), but its collision model was never actually general, and this is the first scenario that needed it to be.

5. The open question, answered directly: does closed-loop replanning fix the symmetric saddle?

The previous deliverable ended with a documented limitation: a perfectly symmetric obstacle placed exactly on the straight-line path creates a true local-optimization saddle point, and asked whether warm-starting each cycle from a slightly-different previous plan would resolve this "for free" in a real closed loop, as opposed to a single open-loop solve.

Tested directly, not assumed: no. With a perfectly symmetric obstacle, a deterministic solver, and a deterministic warm start, there is nothing in the closed loop that introduces the asymmetry needed to break the tie — every cycle re-solves the same symmetric problem the same way and gets the same symmetric (non-avoiding) answer, and the ego collides (test_closed_loop_replanning_does_NOT_break_a_perfectly_symmetric_tie). The saddle is a knife-edge, though, not a robust failure mode: a lateral offset of just 5 centimeters — well within realistic sensor or localization noise — is already enough for the exact same closed loop to find and commit to a real, comfortable detour (test_a_tiny_off_center_offset_is_enough_to_resolve_it). In practice, a real system essentially never sees a perfectly symmetric obstacle placement, which is presumably why this doesn't tend to bite in the field — but it's a real, sharp edge in the math, now confirmed rather than hand-waved.

""" simplex_guard.py ----------------- A non-neural, analytically-verifiable runtime safety monitor ("Simplex architecture" pattern: a high-performance, unverified controller supervised by a simple, provably-safe fallback controller that can override it). No learned components, no floating hyperparameters that aren't physically motivated. 2. Deterministic and side-effect free: same inputs -> same outputs, always. Coordinate conventions ----------------------- - Ego-centric frame at the *current* planning instant: x = forward (m), y = left (m), heading = 0 rad along +x. - Trajectory state per timestep: (x, y, heading, speed, curvature) x, y : position (m), ego frame at planning time heading : heading angle (rad), 0 = straight ahead speed : longitudinal speed (m/s), signed (>=0 expected) curvature : path curvature (1/m), signed (+ = turning left) - Occupancy grid: 2D boolean/float array, shape (H, W), ego-centric, with the ego position at (origin_row, origin_col) and cell (i, j) covering the physical point: x = (j - origin_col) * resolution y = (origin_row - i) * resolution i.e. row index decreases as x increases is NOT assumed; we index by explicit origin + resolution so the convention is unambiguous and tested (see tests for exact mapping). In a real program these would be set (and re-verified) by a formal hazard analysis / FMEA, not picked by an engineer's judgement call — the values here are reasonable defaults for a passenger vehicle, clearly labelled as such, and every one is overridable. """ # --- Time-to-collision (TTC) --- # NHTSA / SAE literature commonly treats TTC < 1.5s as an imminent # crash regime for forward collision warning systems; we use 1.5s # as the hard trigger and 3.0s as an early/soft trigger band. ttc_hard_threshold_s: float = 1.5 ttc_soft_threshold_s: float = 3.0 # --- Driver/system reaction + actuation latency budget --- # Time between "guard decides to intervene" and "commanded # deceleration is actually being produced by the vehicle" # (brake actuator lag, communication latency, etc). actuation_latency_s: float = 0.15 # --- Braking physics --- # Max achievable deceleration is mu * g, derated by a safety # margin because mu estimates are noisy and we don't want to plan # trajectories that assume the theoretical limit. gravity_mps2: float = 9.81 friction_default: float = 0.7 # dry asphalt, conservative default friction_derate: float = 0.85 # use 85% of mu*g as "available" decel min_clearance_m: float = 2.0 # minimum standoff distance, stopped # --- Lateral / cornering --- # Fraction of friction budget allowed to be spent on lateral accel # before the guard considers the corner unsafe at the commanded # speed. Left-over budget (1 - this) is reserved for combined # braking, per a simplified friction-circle argument. lateral_friction_budget: float = 0.6 # --- Occupancy / clearance scanning --- ego_half_width_m: float = 1.0 # vehicle half-width for footprint sweep default_resolution_m: float = 0.5 # occupancy grid cell size (m) # --- Safe-stop fallback profile --- # Deceleration commanded by the guard's own fallback trajectory. # Intentionally less aggressive than max_available so the fallback # itself doesn't risk a rear-end / loss of control, unless an # emergency-stop is required (see EMERGENCY case). fallback_comfort_decel_mps2: float = 3.0 fallback_emergency_decel_mps2: float = 7.0 # near max on dry road def available_decel_mps2(self, mu: Optional[float] = None) -> float: mu = self.friction_default if mu is None else mu return self.friction_derate * mu * self.gravity_mps2 def max_lateral_accel_mps2(self, mu: Optional[float] = None) -> float: mu = self.friction_default if mu is None else mu return self.lateral_friction_budget * mu * self.gravity_mps2 # -------------------------------------------------------------------------- # Result types # -------------------------------------------------------------------------- class ViolationType(str, Enum): NONE = "none" TTC_HARD = "ttc_hard" TTC_SOFT = "ttc_soft" STOPPING_DISTANCE = "stopping_distance" LATERAL_ACCEL = "lateral_accel" INFEASIBLE_DECEL = "infeasible_decel_request" INVALID_SENSOR_INPUT = "invalid_sensor_input" class FallbackMode(str, Enum): NONE = "none" COMFORT_STOP = "comfort_stop" EMERGENCY_STOP = "emergency_stop" SPEED_LIMIT_CORNER = "speed_limit_corner" class GuardDecision(NamedTuple): """Single-sample (unbatched) guard decision. Kept flat and simple so it is trivial to log, serialize, and unit test.""" overridden: bool violations: Tuple[ViolationType, ...] fallback_mode: FallbackMode ttc_s: Optional[float] required_stopping_distance_m: Optional[float] available_clearance_m: Optional[float] max_lateral_accel_mps2: Optional[float] commanded_lateral_accel_mps2: Optional[float] # -------------------------------------------------------------------------- # Core physics helpers (pure functions — the auditable core) # -------------------------------------------------------------------------- def time_to_collision(distance_m: float, closing_speed_mps: float) -> Optional[float]: """TTC = distance / closing_speed. Returns None (i.e. "no TTC concern") if the gap is not closing (closing_speed <= 0) or if already at/behind the obstacle in a degenerate way handled by the caller. Never divides by zero. """ if closing_speed_mps <= 1e-6: return None if distance_m <= 0.0: return 0.0 return distance_m / closing_speed_mps def required_stopping_distance( speed_mps: float, decel_mps2: float, reaction_time_s: float, ) -> float: """Distance needed to come to a full stop from `speed_mps`, given a reaction/latency window during which speed is assumed constant (worst case: no deceleration yet applied), followed by constant deceleration `decel_mps2`. d = v * t_reaction + v^2 / (2 * decel) """ if decel_mps2 <= 0: raise ValueError("decel_mps2 must be > 0") speed_mps = max(speed_mps, 0.0) reaction_distance = speed_mps * reaction_time_s braking_distance = (speed_mps ** 2) / (2.0 * decel_mps2) return reaction_distance + braking_distance def lateral_acceleration(speed_mps: float, curvature_per_m: float) -> float: """a_lat = v^2 * kappa. Sign follows curvature sign.""" return (speed_mps ** 2) * curvature_per_m def max_safe_cornering_speed( curvature_per_m: float, max_lateral_accel_mps2: float ) -> float: """Max speed such that |v^2 * kappa| <= max_lateral_accel. Returns +inf for (near-)straight paths. """ k = abs(curvature_per_m) if k < 1e-9: return float("inf") return math.sqrt(max_lateral_accel_mps2 / k) # -------------------------------------------------------------------------- # Occupancy scanning (still analytic: nearest-obstacle-ahead lookup) # -------------------------------------------------------------------------- def nearest_obstacle_distance_ahead( occupancy: np.ndarray, origin_row: int, origin_col: int, resolution_m: float, heading_rad: float, half_width_m: float, max_range_m: float, ) -> Optional[float]: """Ray/footprint sweep: march forward along `heading_rad` from the ego origin cell in fixed physical steps, and at each step check a lateral band of width `2 * half_width_m` for occupied cells. Returns the distance (m) to the first occupied cell, or `None` if nothing is found within `max_range_m`. Returning `None` (rather than `max_range_m`) on a miss is a deliberate safety choice: silently substituting the scan boundary for "clear" would let a caller compute a spurious, falsely reassuring TTC/clearance number from a distance that was never actually observed to be clear. Callers must treat `None` as "no obstacle detected within sensing range" and must not manufacture a TTC from it. This is intentionally a simple, easily-reasoned-about sweep (not a learned occupancy-to-distance regressor) so its correctness can be argued directly from the grid semantics. """ if not math.isfinite(max_range_m) or max_range_m <= 0: raise ValueError(f"max_range_m must be finite and positive, got {max_range_m}") h, w = occupancy.shape step_m = resolution_m * 0.5 # oversample to avoid skipping thin cells n_steps = int(max_range_m / step_m) cos_h, sin_h = math.cos(heading_rad), math.sin(heading_rad) # Precompute lateral offsets (perpendicular to heading) to sweep # the vehicle footprint width. lateral_offsets = np.arange( -half_width_m, half_width_m + 1e-9, resolution_m ) perp_x, perp_y = -sin_h, cos_h for step in range(1, n_steps + 1): dist = step * step_m cx = dist * cos_h cy = dist * sin_h for lat in lateral_offsets: px = cx + lat * perp_x py = cy + lat * perp_y col = origin_col + int(round(px / resolution_m)) row = origin_row - int(round(py / resolution_m)) if 0 <= row < h and 0 <= col < w: if occupancy[row, col]: return dist return None # -------------------------------------------------------------------------- # Fallback trajectory generation # -------------------------------------------------------------------------- def generate_stop_trajectory( ego_speed_mps: float, decel_mps2: float, horizon_steps: int, dt_s: float, heading_rad: float = 0.0, ) -> np.ndarray: """Analytic constant-deceleration-to-stop trajectory in the (x, y, heading, speed, curvature) state layout used elsewhere in the stack. Heading and curvature are held at their current values (straight-line braking is the safest default fallback: it does not introduce a new lateral-accel risk). Returns array of shape (horizon_steps, 5). """ traj = np.zeros((horizon_steps, 5), dtype=np.float64) v = max(ego_speed_mps, 0.0) x = 0.0 for t in range(horizon_steps): traj[t, 0] = x traj[t, 1] = 0.0 traj[t, 2] = heading_rad traj[t, 3] = v traj[t, 4] = 0.0 # zero curvature: hold lane, no new turn risk # advance x += v * dt_s - 0.5 * decel_mps2 * dt_s ** 2 v = max(v - decel_mps2 * dt_s, 0.0) return traj def generate_speed_limited_trajectory( base_trajectory: np.ndarray, max_speed_mps: float ) -> np.ndarray: """Clip a candidate trajectory's speed profile to a safe cornering speed, leaving position/heading/curvature untouched. Used for the lateral-acceleration violation, where the *path* is fine but the *speed on that path* is not. """ out = base_trajectory.copy() out[:, 3] = np.minimum(out[:, 3], max_speed_mps) return out # -------------------------------------------------------------------------- # The guard itself # -------------------------------------------------------------------------- class SimplexGuard: """Stateless (per-call) analytical safety supervisor. Usage: guard = SimplexGuard(config) decision, safe_traj, overridden = guard.check_and_override( candidate_traj, ego_state, occupancy, dt_s, resolution_m, mu ) `candidate_traj`: np.ndarray (T, 5) — the upstream planner's proposed trajectory in ego frame, state layout (x, y, heading, speed, curvature). `ego_state`: np.ndarray (5,) — current (x=0, y=0, heading=0, speed, curvature). Position/heading are 0 by construction since the trajectory is expressed in the ego frame at the current instant. `occupancy`: np.ndarray (H, W) boolean/float grid, ego-centric. """ def __init__(self, config: Optional[SimplexGuardConfig] = None): self.config = config or SimplexGuardConfig() # -- public API --------------------------------------------------- def check_and_override( self, candidate_traj: np.ndarray, ego_state: np.ndarray, occupancy: Optional[np.ndarray], dt_s: float, resolution_m: Optional[float] = None, mu: Optional[float] = None, occupancy_origin: Optional[Tuple[int, int]] = None, ) -> Tuple[GuardDecision, np.ndarray, bool]: cfg = self.config resolution_m = resolution_m or cfg.default_resolution_m candidate_traj = np.asarray(candidate_traj, dtype=np.float64) ego_state = np.asarray(ego_state, dtype=np.float64) if candidate_traj.ndim != 2 or candidate_traj.shape[1] != 5: raise ValueError("candidate_traj must have shape (T, 5)") T = candidate_traj.shape[0] # --- 0. Sensor sanity check (fail-safe on corrupted input) -- # A monitor that trusts NaN/inf sensor data enough to "pass" # is worse than useless. If the ego state or trajectory # contains any non-finite value, treat it as an automatic # violation and go straight to the most conservative fallback # available (max deceleration, straight-line hold) rather than # attempting arithmetic on garbage data. if not np.all(np.isfinite(ego_state)) or not np.all(np.isfinite(candidate_traj)): safe_speed_guess = 0.0 if np.isfinite(ego_state[3]): safe_speed_guess = max(float(ego_state[3]), 0.0) safe_heading_guess = float(ego_state[2]) if np.isfinite(ego_state[2]) else 0.0 safe_traj = generate_stop_trajectory( ego_speed_mps=safe_speed_guess, decel_mps2=cfg.fallback_emergency_decel_mps2, horizon_steps=T, dt_s=dt_s, heading_rad=safe_heading_guess, ) decision = GuardDecision( overridden=True, violations=(ViolationType.INVALID_SENSOR_INPUT,), fallback_mode=FallbackMode.EMERGENCY_STOP, ttc_s=None, required_stopping_distance_m=None, available_clearance_m=None, max_lateral_accel_mps2=None, commanded_lateral_accel_mps2=None, ) return decision, safe_traj, True ego_speed = float(ego_state[3]) ego_heading = float(ego_state[2]) violations: List[ViolationType] = [] available_decel = cfg.available_decel_mps2(mu) max_lat_accel = cfg.max_lateral_accel_mps2(mu) # --- 1. Clearance / TTC / stopping-distance check --------- ttc = None req_stop_dist = None avail_clearance = None if occupancy is not None: h, w = occupancy.shape origin_row, origin_col = occupancy_origin or (h // 2, w // 2) max_range = required_stopping_distance( speed_mps=max(ego_speed, 1.0), decel_mps2=cfg.fallback_comfort_decel_mps2, reaction_time_s=cfg.actuation_latency_s, ) + 20.0 # generous scan range beyond worst-case stop raw_clearance = nearest_obstacle_distance_ahead( occupancy=occupancy, origin_row=origin_row, origin_col=origin_col, resolution_m=resolution_m, heading_rad=ego_heading, half_width_m=cfg.ego_half_width_m, max_range_m=max_range, ) if raw_clearance is None: # Nothing detected within sensing range: genuinely no # TTC/stopping-distance concern. Do NOT fabricate a # clearance value from the scan boundary — that would # produce a falsely reassuring (or falsely alarming) # number for a region we never actually observed. avail_clearance = None ttc = None req_stop_dist = None else: avail_clearance = max(raw_clearance - cfg.min_clearance_m, 0.0) ttc = time_to_collision(avail_clearance, ego_speed) req_stop_dist = required_stopping_distance( speed_mps=ego_speed, decel_mps2=available_decel, reaction_time_s=cfg.actuation_latency_s, ) if ttc is not None and ttc < cfg.ttc_hard_threshold_s: violations.append(ViolationType.TTC_HARD) elif ttc is not None and ttc < cfg.ttc_soft_threshold_s: violations.append(ViolationType.TTC_SOFT) if req_stop_dist > avail_clearance: violations.append(ViolationType.STOPPING_DISTANCE) # --- 2. Lateral acceleration feasibility over the horizon -- speeds = candidate_traj[:, 3] curvatures = candidate_traj[:, 4] lat_accels = speeds ** 2 * curvatures worst_idx = int(np.argmax(np.abs(lat_accels))) worst_lat_accel = float(lat_accels[worst_idx]) if abs(worst_lat_accel) > max_lat_accel: violations.append(ViolationType.LATERAL_ACCEL) # --- 3. Decide fallback ------------------------------------- fallback_mode = FallbackMode.NONE safe_traj = candidate_traj overridden = False has_ttc_hard = ViolationType.TTC_HARD in violations has_stop_dist = ViolationType.STOPPING_DISTANCE in violations has_lat = ViolationType.LATERAL_ACCEL in violations has_ttc_soft = ViolationType.TTC_SOFT in violations if has_ttc_hard or has_stop_dist: fallback_mode = FallbackMode.EMERGENCY_STOP safe_traj = generate_stop_trajectory( ego_speed_mps=ego_speed, decel_mps2=cfg.fallback_emergency_decel_mps2, horizon_steps=T, dt_s=dt_s, heading_rad=ego_heading, ) overridden = True elif has_lat: safe_speed = max_safe_cornering_speed( curvature_per_m=curvatures[worst_idx], max_lateral_accel_mps2=max_lat_accel, ) fallback_mode = FallbackMode.SPEED_LIMIT_CORNER safe_traj = generate_speed_limited_trajectory(candidate_traj, safe_speed) overridden = True elif has_ttc_soft: fallback_mode = FallbackMode.COMFORT_STOP safe_traj = generate_stop_trajectory( ego_speed_mps=ego_speed, decel_mps2=cfg.fallback_comfort_decel_mps2, horizon_steps=T, dt_s=dt_s, heading_rad=ego_heading, ) overridden = True if not violations: violations = [ViolationType.NONE] decision = GuardDecision( overridden=overridden, violations=tuple(violations), fallback_mode=fallback_mode, ttc_s=ttc, required_stopping_distance_m=req_stop_dist, available_clearance_m=avail_clearance, max_lateral_accel_mps2=max_lat_accel, commanded_lateral_accel_mps2=worst_lat_accel, ) return decision, safe_traj, overridden # -- batched convenience wrapper ----------------------------------- def check_and_override_batch( self, candidate_traj_batch: np.ndarray, ego_state_batch: np.ndarray, occupancy_batch: Optional[np.ndarray], dt_s: float, resolution_m: Optional[float] = None, mu: Optional[Sequence[float]] = None, ) -> Tuple[List[GuardDecision], np.ndarray, np.ndarray]: """Batch wrapper matching the shape conventions used by the surrounding torch-based stack: (B, T, 5) trajectories, (B, 5) ego states, (B, H, W) occupancy grids. Implemented as a plain Python loop over the batch — the guard's per-sample cost is small (see benchmark in the test suite) and a loop keeps the core logic simple to audit, which matters more here than vectorized throughput. """ B = candidate_traj_batch.shape[0] decisions: List[GuardDecision] = [] out_traj = np.zeros_like(candidate_traj_batch, dtype=np.float64) overridden_flags = np.zeros(B, dtype=bool) for b in range(B): occ_b = occupancy_batch[b] if occupancy_batch is not None else None mu_b = mu[b] if mu is not None else None decision, safe_traj, overridden = self.check_and_override( candidate_traj_batch[b], ego_state_batch[b], occ_b, dt_s, resolution_m, mu_b, ) decisions.append(decision) out_traj[b] = safe_traj overridden_flags[b] = overridden return decisions, out_traj, overridden_flags 

closed_loop_sim.py

""" closed_loop_sim.py -------------------- A small, fully-synthetic closed-loop simulator used to stress-test the Simplex Guard (see simplex_guard.py) across a *sequence* of decisions over time, not just isolated snapshots. This exists to catch a class of bugs unit tests structurally cannot: oscillating overrides, fallback trajectories that are too gentle once actually integrated forward, or behavior that only breaks after several cycles of feedback between the guard's output and the world's response to it. No real driving data is used anywhere in this file. Every vehicle, obstacle, and scenario is a scripted, hand-specified kinematic model. Scope and honesty about limitations ------------------------------------ This is a toy simulator, not a validation platform: - Kinematics are a simple unicycle-style model integrated with explicit (forward) Euler steps, not a validated vehicle dynamics model. - One "sim tick" == one guard planning cycle (no separate high-rate reactive loop as in the full FSD v12 design doc's async architecture) -- this keeps the harness simple to audit at the cost of not testing the multi-rate execution boundary. - Collision checking is longitudinal-only (single-lane car-following geometry): fine for the scenarios below, not a general 2D collision model. - The Simplex Guard itself is stateless per call, by design (see simplex_guard.py docstring). This simulator deliberately includes a scenario that surfaces the real consequence of that statelessness under sensor dropout, rather than hiding it. Coordinate conventions ----------------------- World frame: fixed at simulation start, ego begins at the origin with heading 0 (facing +x). Actors (lead vehicles / obstacles) move along the same +x axis at a fixed lateral offset y (0.0 for same-lane). Ego-frame occupancy grids passed to the guard follow the exact same convention as simplex_guard.py's `nearest_obstacle_distance_ahead`: ego at (origin_row, origin_col), +x forward = +col, +y left = -row. """ from __future__ import annotations import math from dataclasses import dataclass, field from typing import Callable, List, Optional, Sequence, Tuple import numpy as np from simplex_guard import ( FallbackMode, GuardDecision, SimplexGuard, SimplexGuardConfig, ViolationType, ) # -------------------------------------------------------------------------- # Kinematics # -------------------------------------------------------------------------- @dataclass class VehicleState: x: float y: float = 0.0 heading: float = 0.0 speed: float = 0.0 def step_kinematics( state: VehicleState, accel: float, curvature: float, dt: float ) -> VehicleState: """Explicit-Euler unicycle-style kinematic update. heading_dot = speed * curvature x_dot = speed * cos(heading) y_dot = speed * sin(heading) speed_dot = accel This is intentionally simple (not RK4, not a bicycle model with slip) -- it is sufficient to expose feedback/timing bugs in the guard's decision loop, which is what this harness is for. It is NOT a substitute for a validated vehicle dynamics simulator. """ new_x = state.x + state.speed * math.cos(state.heading) * dt new_y = state.y + state.speed * math.sin(state.heading) * dt new_heading = state.heading + state.speed * curvature * dt new_speed = max(state.speed + accel * dt, 0.0) return VehicleState(new_x, new_y, new_heading, new_speed) # -------------------------------------------------------------------------- # Scripted actors (lead vehicles / static obstacles) # -------------------------------------------------------------------------- @dataclass class AccelSegment: """An acceleration held constant from `t_start_s` (measured relative to the actor's own spawn time) until the next segment's start.""" t_start_s: float accel_mps2: float @dataclass class ScriptedActor: """A longitudinally-moving actor (lead vehicle or static obstacle) with a scripted acceleration profile, and a spawn time that lets a single mechanism represent both "present from the start" (spawn at t=0) and "sudden cut-in / occlusion reveal" (spawn later, at a gap defined relative to the ego's position at that instant). """ spawn_time_s: float spawn_gap_ahead_m: float # world x offset from ego's position AT SPAWN TIME spawn_speed_mps: float accel_schedule: List[AccelSegment] = field(default_factory=list) length_m: float = 4.5 width_m: float = 2.0 lateral_offset_m: float = 0.0 # 0.0 = same lane as ego def accel_at(self, elapsed_since_spawn_s: float) -> float: if not self.accel_schedule: return 0.0 active = 0.0 for seg in sorted(self.accel_schedule, key=lambda s: s.t_start_s): if seg.t_start_s <= elapsed_since_spawn_s: active = seg.accel_mps2 else: break return active @dataclass class ActorRuntime: """Mutable simulation state for one ScriptedActor.""" spawned: bool = False x: float = 0.0 v: float = 0.0 # -------------------------------------------------------------------------- # Naive / optimistic planner (the "upstream AI stack" stand-in) # -------------------------------------------------------------------------- class CruisePlanner: """A deliberately obstacle-blind planner: it tries to reach and hold a target cruise speed and follow a (possibly time-varying) commanded curvature, with NO awareness of obstacles. This represents the realistic worst case the guard must handle: an upstream perception/planning failure, a stale plan, or a genuinely overconfident neural planner. """ def __init__( self, target_speed_mps: float, comfort_accel_mps2: float = 2.0, comfort_decel_mps2: float = 2.0, curvature_fn: Optional[Callable[[float], float]] = None, ): self.target_speed_mps = target_speed_mps self.comfort_accel_mps2 = comfort_accel_mps2 self.comfort_decel_mps2 = comfort_decel_mps2 self.curvature_fn = curvature_fn or (lambda t: 0.0) def curvature_at(self, t: float) -> float: return self.curvature_fn(t) def generate( self, current_speed_mps: float, t: float, T: int, dt: float ) -> np.ndarray: """Builds a (T, 5) trajectory in the EGO LOCAL frame (x=0, y=0, heading=0 at the current instant), extrapolating toward the target cruise speed at a fixed comfortable accel/decel, using curvature_fn(t) held constant over the horizon at its value at the current planning instant `t`. It never looks at obstacles -- that's the guard's job. """ traj = np.zeros((T, 5), dtype=np.float64) v = current_speed_mps x = 0.0 heading = 0.0 kappa = self.curvature_fn(t) for i in range(T): traj[i] = [x, 0.0, heading, v, kappa] if v < self.target_speed_mps: accel = self.comfort_accel_mps2 elif v > self.target_speed_mps: accel = -self.comfort_decel_mps2 else: accel = 0.0 v = max(v + accel * dt, 0.0) heading += v * kappa * dt x += v * math.cos(heading) * dt return traj # -------------------------------------------------------------------------- # Ego-frame occupancy grid construction # -------------------------------------------------------------------------- def build_occupancy_grid( ego: VehicleState, visible_actors_world: Sequence[Tuple[float, float, float, float]], half_extent_m: float, resolution_m: float, ) -> Tuple[np.ndarray, Tuple[int, int]]: """Builds an ego-centric occupancy grid from a list of (world_x, world_y, length_m, width_m) obstacle footprints, using the exact same (row, col) convention as simplex_guard.nearest_obstacle_distance_ahead: col = origin_col + round(x_local / res) row = origin_row - round(y_local / res) where (x_local, y_local) is the obstacle position rotated into the ego's current heading frame. """ size = int(2 * half_extent_m / resolution_m) + 1 origin_row = origin_col = size // 2 grid = np.zeros((size, size), dtype=bool) cos_h, sin_h = math.cos(-ego.heading), math.sin(-ego.heading) for wx, wy, length, width in visible_actors_world: dx, dy = wx - ego.x, wy - ego.y # rotate world offset into ego-heading frame x_local = dx * cos_h - dy * sin_h y_local = dx * sin_h + dy * cos_h half_l, half_w = length / 2.0, width / 2.0 xs = np.arange(x_local - half_l, x_local + half_l + 1e-9, resolution_m * 0.5) ys = np.arange(y_local - half_w, y_local + half_w + 1e-9, resolution_m * 0.5) for gx in xs: for gy in ys: col = origin_col + int(round(gx / resolution_m)) row = origin_row - int(round(gy / resolution_m)) if 0 <= row < size and 0 <= col < size: grid[row, col] = True return grid, (origin_row, origin_col) # stochastic_ilqr.py

""" stochastic_ilqr.py -------------------- A from-scratch iLQR (iterative Linear Quadratic Regulator) trajectory optimizer for a kinematic unicycle robot, augmented with a STOCHASTIC RISK TERM that turns "epistemic uncertainty x occupancy" into a real-time-tractable, differentiable addition to the running cost -- this is Improvement #1 from the FSD v12 design document, implemented and validated end to end. Why this is the interesting piece to build -------------------------------------------- A standard MPC/iLQR cost only knows about a *point estimate* of where obstacles are (occupancy). It has no way to be more cautious in a region the perception system is unsure about versus a region it is confident is clear. The fix used here: maintain two scalar fields over the workspace -- occupancy(p) in [0, 1] : how likely something occupies point p uncertainty(p) in [0, 1] : how unsure the perception system is about that likelihood at point p and add a risk cost term l_risk(p) = risk_weight * uncertainty(p) * occupancy(p) to the running cost at every timestep along the trajectory. A region with high occupancy but LOW uncertainty (a confidently-detected wall) is treated as a normal hard-ish cost the planner will route around anyway. A region with moderate occupancy AND high uncertainty (e.g. "might be a pedestrian behind that parked van, sensor isn't sure") now carries extra cost specifically because it's unsure -- pushing the planner toward a route with a clearer, more confidently-assessed margin, even when the point-estimate occupancy alone wouldn't have forced a detour. Both fields are represented as sums of smooth Gaussian "bumps," which makes the risk term's gradient and Hessian available in closed form (no autodiff framework, no finite differences) -- this directly implements the design doc's stated refinement of replacing finite-difference Jacobians with analytic ones, and the analytic Jacobians for the *dynamics* are implemented the same way, for the same reason: finite-differencing inside a real-time control loop is expensive and noisy; closed-form derivatives are cheap and exact. Everything below is validated against finite differences in the test suite as an explicit correctness check, not just asserted. Scope and honesty about limitations -------------------------------------- - The dynamics model is a kinematic unicycle (state = x, y, heading; control = speed, turn-rate), not a full vehicle dynamics model with slip, tire forces, or actuator lag. - The risk field is a synthetic sum of Gaussian bumps, not a real perception system's uncertainty/occupancy output. The point of this exercise is to validate that the MATH and the OPTIMIZER correctly turn "uncertainty x occupancy" into risk-averse routing -- not to claim this is a deployable perception interface. - Obstacle avoidance here is soft (cost-based), not the hard constraint enforcement a real system would layer on top (that's what the Simplex Guard, built previously, is for). """ from __future__ import annotations import math from dataclasses import dataclass, field from typing import Callable, List, Optional, Sequence, Tuple import numpy as np # ========================================================================== # Scalar fields (uncertainty / occupancy), with analytic derivatives # ========================================================================== @dataclass(frozen=True) class GaussianBump: """An isotropic Gaussian bump in 2D: f(p) = amplitude * exp(-||p - center||^2 / (2 * sigma^2)) Closed-form gradient and Hessian (used directly by iLQR's cost quadratic expansion -- no autodiff, no finite differences): grad f(p) = f(p) * (-(p - center) / sigma^2) Hess f(p) = f(p) * ( outer(d, d) / sigma^4 - I / sigma^2 ), d = p - center """ center: Tuple[float, float] amplitude: float sigma: float def __post_init__(self): if self.sigma <= 0: raise ValueError("sigma must be > 0") def value(self, p: np.ndarray) -> float: d = p - np.asarray(self.center) return float(self.amplitude * math.exp(-float(d @ d) / (2.0 * self.sigma ** 2))) def gradient(self, p: np.ndarray) -> np.ndarray: d = p - np.asarray(self.center) f = self.value(p) return f * (-d / self.sigma ** 2) def hessian(self, p: np.ndarray) -> np.ndarray: d = p - np.asarray(self.center) f = self.value(p) outer = np.outer(d, d) return f * (outer / self.sigma ** 4 - np.eye(2) / self.sigma ** 2) @dataclass class ScalarField: """A sum of GaussianBumps, clipped to [0, 1] in VALUE ONLY for interpretation purposes (occupancy/uncertainty are probabilities). The clip is intentionally NOT applied inside gradient/Hessian -- doing so would make the field non-differentiable at the clip boundary. In practice the bump amplitudes are chosen so the sum stays within [0, 1] almost everywhere for the scenarios used here; this is documented and tested explicitly (see `test_field_values_stay_in_unit_range_for_test_scenarios`). """ bumps: List[GaussianBump] = field(default_factory=list) def value(self, p: np.ndarray) -> float: return float(sum(b.value(p) for b in self.bumps)) def gradient(self, p: np.ndarray) -> np.ndarray: if not self.bumps: return np.zeros(2) return sum(b.gradient(p) for b in self.bumps) def hessian(self, p: np.ndarray) -> np.ndarray: if not self.bumps: return np.zeros((2, 2)) return sum(b.hessian(p) for b in self.bumps) @dataclass class RiskField: """risk(p) = uncertainty(p) * occupancy(p), with exact gradient and Hessian via the product rule: h = u * o grad h = u * grad_o + o * grad_u Hess h = u * Hess_o + o * Hess_u + outer(grad_u, grad_o) + outer(grad_o, grad_u) """ uncertainty: ScalarField occupancy: ScalarField def value(self, p: np.ndarray) -> float: return self.uncertainty.value(p) * self.occupancy.value(p) def gradient(self, p: np.ndarray) -> np.ndarray: u = self.uncertainty.value(p) o = self.occupancy.value(p) gu = self.uncertainty.gradient(p) go = self.occupancy.gradient(p) return u * go + o * gu def hessian(self, p: np.ndarray) -> np.ndarray: u = self.uncertainty.value(p) o = self.occupancy.value(p) gu = self.uncertainty.gradient(p) go = self.occupancy.gradient(p) hu = self.uncertainty.hessian(p) ho = self.occupancy.hessian(p) return u * ho + o * hu + np.outer(gu, go) + np.outer(go, gu) # ========================================================================== # Dynamics: kinematic unicycle, with analytic Jacobians # ========================================================================== STATE_DIM = 3 # [x, y, heading] CONTROL_DIM = 2 # [speed, turn_rate] def unicycle_step(x: np.ndarray, u: np.ndarray, dt: float) -> np.ndarray: """x_{t+1} = f(x_t, u_t): x' = x + v * cos(heading) * dt y' = y + v * sin(heading) * dt heading' = heading + omega * dt """ px, py, heading = x v, omega = u return np.array( [ px + v * math.cos(heading) * dt, py + v * math.sin(heading) * dt, heading + omega * dt, ] ) def unicycle_jacobians(x: np.ndarray, u: np.ndarray, dt: float) -> Tuple[np.ndarray, np.ndarray]: """Analytic df/dx (A, 3x3) and df/du (B, 3x2) for the unicycle step. df/dx = [[1, 0, -v*sin(h)*dt], [0, 1, v*cos(h)*dt], [0, 0, 1 ]] df/du = [[cos(h)*dt, 0], [sin(h)*dt, 0], [0, dt]] """ _, _, heading = x v, _ = u A = np.array( [ [1.0, 0.0, -v * math.sin(heading) * dt], [0.0, 1.0, v * math.cos(heading) * dt], [0.0, 0.0, 1.0], ] ) B = np.array( [ [math.cos(heading) * dt, 0.0], [math.sin(heading) * dt, 0.0], [0.0, dt], ] ) return A, B # ========================================================================== # Cost function # ========================================================================== @dataclass class CostConfig: Q_running: np.ndarray # 3x3, running state cost (usually small/zero) R: np.ndarray # 2x2, control effort cost Qf: np.ndarray # 3x3, terminal state cost (drives goal-reaching) goal: np.ndarray # (3,) goal state risk_weight: float = 0.0 risk_field: Optional[RiskField] = None def stage_cost(self, x: np.ndarray, u: np.ndarray) -> float: dx = x - self.goal cost = 0.5 * dx @ self.Q_running @ dx + 0.5 * u @ self.R @ u if self.risk_weight > 0 and self.risk_field is not None: cost += self.risk_weight * self.risk_field.value(x[:2]) return float(cost) def terminal_cost(self, x: np.ndarray) -> float: dx = x - self.goal return float(0.5 * dx @ self.Qf @ dx) def stage_derivatives( self, x: np.ndarray, u: np.ndarray ) -> Tuple[np.ndarray, np.ndarray, np.ndarray, np.ndarray, np.ndarray]: """Returns (l_x, l_u, l_xx, l_uu, l_ux).""" dx = x - self.goal l_x = self.Q_running @ dx l_u = self.R @ u l_xx = self.Q_running.copy() l_uu = self.R.copy() l_ux = np.zeros((CONTROL_DIM, STATE_DIM)) if self.risk_weight > 0 and self.risk_field is not None: p = x[:2] g = self.risk_field.gradient(p) # (2,) H = self.risk_field.hessian(p) # (2,2) l_x = l_x.copy() l_x[:2] += self.risk_weight * g l_xx = l_xx.copy() l_xx[:2, :2] += self.risk_weight * H # No u- or heading-dependence in the risk term, so l_u, # l_uu, l_ux get no contribution from it. return l_x, l_u, l_xx, l_uu, l_ux def terminal_derivatives(self, x: np.ndarray) -> Tuple[np.ndarray, np.ndarray]: dx = x - self.goal return self.Qf @ dx, self.Qf.copy() # ========================================================================== # iLQR solver # ========================================================================== @dataclass class ILQRResult: X: np.ndarray # (T+1, 3) U: np.ndarray # (T, 2) cost_history: List[float] converged: bool iterations: int final_regularization: float class ILQRSolver: def __init__( self, cost: CostConfig, dt: float = 0.1, max_iters: int = 100, cost_tol: float = 1e-5, reg_init: float = 1.0, reg_min: float = 1e-6, reg_max: float = 1e10, reg_factor: float = 2.0, line_search_alphas: Optional[Sequence[float]] = None, max_control: Optional[np.ndarray] = None, ): self.cost = cost self.dt = dt self.max_iters = max_iters self.cost_tol = cost_tol self.reg_init = reg_init self.reg_min = reg_min self.reg_max = reg_max self.reg_factor = reg_factor self.line_search_alphas = list(line_search_alphas or [1.0, 0.5, 0.25, 0.1, 0.05, 0.01]) self.max_control = max_control # -- helpers --------------------------------------------------------- def _rollout(self, x0: np.ndarray, U: np.ndarray) -> np.ndarray: T = U.shape[0] X = np.zeros((T + 1, STATE_DIM)) X[0] = x0 for t in range(T): X[t + 1] = unicycle_step(X[t], U[t], self.dt) return X def _total_cost(self, X: np.ndarray, U: np.ndarray) -> float: T = U.shape[0] total = sum(self.cost.stage_cost(X[t], U[t]) for t in range(T)) total += self.cost.terminal_cost(X[T]) return total def _clip_control(self, u: np.ndarray) -> np.ndarray: if self.max_control is None: return u return np.clip(u, -self.max_control, self.max_control) # -- backward pass ----------------------------------------------------- def _backward_pass( self, X: np.ndarray, U: np.ndarray, reg: float ) -> Optional[Tuple[List[np.ndarray], List[np.ndarray], float]]: """Returns (k_list, K_list, expected_improvement) or None if Q_uu could not be made positive-definite even at the current regularization (caller should increase reg and retry). `expected_improvement` is the standard DDP/iLQR predicted cost reduction sum_t [ -(Q_u^T k_t + 0.5 * k_t^T Q_uu k_t) ] -- computed directly from the backward pass, independent of whether a forward-pass line search actually finds an improving step. This is what lets the solver correctly recognize convergence when the cost is ALREADY at (or essentially at) its minimum: in that case Q_u ~= 0 everywhere, expected_improvement ~= 0, and no line-search step could ever reduce a cost that is already minimal -- that is a sign of convergence, not a sign that regularization needs to keep increasing forever. """ T = U.shape[0] Vx, Vxx = self.cost.terminal_derivatives(X[T]) k_list: List[np.ndarray] = [None] * T # type: ignore K_list: List[np.ndarray] = [None] * T # type: ignore expected_improvement = 0.0 for t in reversed(range(T)): x, u = X[t], U[t] A, B = unicycle_jacobians(x, u, self.dt) l_x, l_u, l_xx, l_uu, l_ux = self.cost.stage_derivatives(x, u) Q_x = l_x + A.T @ Vx Q_u = l_u + B.T @ Vx Q_xx = l_xx + A.T @ Vxx @ A Q_uu = l_uu + B.T @ Vxx @ B Q_ux = l_ux + B.T @ Vxx @ A Q_uu_reg = Q_uu + reg * np.eye(CONTROL_DIM) # Positive-definiteness check via Cholesky; signals the # caller to increase regularization and retry the WHOLE # backward pass if it fails partway through (standard # DDP/iLQR regularization scheme). try: L = np.linalg.cholesky(Q_uu_reg) except np.linalg.LinAlgError: return None Q_uu_inv = np.linalg.inv(Q_uu_reg) k = -Q_uu_inv @ Q_u K = -Q_uu_inv @ Q_ux expected_improvement += -(Q_u @ k + 0.5 * k @ Q_uu @ k) Vx = Q_x + K.T @ Q_uu @ k + K.T @ Q_u + Q_ux.T @ k Vxx = Q_xx + K.T @ Q_uu @ K + K.T @ Q_ux + Q_ux.T @ K Vxx = 0.5 * (Vxx + Vxx.T) # enforce symmetry against fp drift k_list[t] = k K_list[t] = K return k_list, K_list, expected_improvement # -- forward pass with line search ------------------------------------- def _forward_pass( self, X: np.ndarray, U: np.ndarray, k_list: List[np.ndarray], K_list: List[np.ndarray], current_cost: float, ) -> Optional[Tuple[np.ndarray, np.ndarray, float]]: T = U.shape[0] for alpha in self.line_search_alphas: X_new = np.zeros_like(X) U_new = np.zeros_like(U) X_new[0] = X[0] for t in range(T): dx = X_new[t] - X[t] u = U[t] + alpha * k_list[t] + K_list[t] @ dx u = self._clip_control(u) U_new[t] = u X_new[t + 1] = unicycle_step(X_new[t], u, self.dt) new_cost = self._total_cost(X_new, U_new) if np.isfinite(new_cost) and new_cost < current_cost: return X_new, U_new, new_cost return None # -- main solve loop ----------------------------------------------------- def solve(self, x0: np.ndarray, U_init: np.ndarray) -> ILQRResult: X = self._rollout(x0, U_init) U = U_init.copy() cost = self._total_cost(X, U) cost_history = [cost] reg = self.reg_init converged = False it = 0 for it in range(1, self.max_iters + 1): backward = None # Increase regularization until the backward pass succeeds # (Q_uu positive-definite at every timestep) or we give up. while backward is None: backward = self._backward_pass(X, U, reg) if backward is None: reg *= self.reg_factor if reg > self.reg_max: return ILQRResult(X, U, cost_history, False, it, reg) k_list, K_list, expected_improvement = backward # Convergence check BEFORE attempting a line search: if the # backward pass itself predicts negligible further # improvement is possible (e.g. we are already at, or # extremely close to, a local optimum -- Q_u ~= 0 # everywhere), no forward-pass step could ever succeed by # construction (there is nothing left to improve), and # that is a sign of CONVERGENCE, not a sign that # regularization needs to keep increasing. Without this # check, a problem that starts exactly at its optimum # (e.g. goal == start) would spin regularization up to # reg_max and incorrectly report failure. if expected_improvement < self.cost_tol: converged = True break result = self._forward_pass(X, U, k_list, K_list, cost) if result is None: # No line-search step improved cost: increase # regularization (be more conservative) and retry. reg *= self.reg_factor if reg > self.reg_max: break continue X_new, U_new, new_cost = result improvement = cost - new_cost X, U, cost = X_new, U_new, new_cost cost_history.append(cost) reg = max(reg / self.reg_factor, self.reg_min) if improvement < self.cost_tol: converged = True break return ILQRResult(X, U, cost_history, converged, it, reg)

11. What this is, and isn't

This validates the integration seams between three previously separately-validated components, and it found real bugs specifically at those seams — not inside any of the three components individually, which is exactly the category of bug integration testing exists to catch. It is explicitly not:

A claim that this architecture is production-ready. The unicycle dynamics, the synthetic Gaussian-bump risk fields, the longitudinal- braking-only guard, and the toy 2D collision model are all the same documented simplifications carried over from the three earlier deliverables.

A performance benchmark. iLQR solves here take on the order of tens of milliseconds each in an unoptimized Python/NumPy sandbox; the original design doc's ~14.5 ms/frame latency budget assumes optimized, likely GPU-accelerated, production code, not this.

A resolution of every previously-documented limitation. The sensor- dropout statelessness limitation from the closed-loop deliverable is still present and still real (Section 4 there) — this integration confirms the planner and guard fail together consistently during a dropout rather than one covering for the other, which is honest but not the same as fixed.

The natural next steps from here, in decreasing order of how directly they follow from what this deliverable found: (1) a small multi-hypothesis seeding fix for the symmetric-saddle knife-edge (try a left- and right-nudged initial guess, keep whichever solves to lower cost) now that Section 5 shows precisely how narrow the failure band is; (2) the bounded "last-known-hazard" hold-over for the guard's statelessness, proposed but not built in the closed-loop deliverable; or (3) the neural-Pacejka tire model (Improvement #2 from the original design doc), which would be the first piece in this series to require an actual dynamics model rather than kinematics.
